# دفتر تصمیم‌های بدهی ملکا (DEBT-DECISIONS)

**سند رسمی · ملکا-شورا-ن۰۱۸-۱۴۰۵ · PN-014 · تاریخ: ۱۴۰۵/۰۷/۱۸ (2026-10-07)**

این دفتر، تصمیم‌های مالک دربارهٔ بدهی‌های «مالک‌سو» انبار بدهی PN-013 را با شرایط،
قیدها و سازوکار پایش ثبت می‌کند. هر تغییر تصمیم = ورودی تازه در همین فایل؛
هیچ تصمیمی بی‌سند حذف یا بازنویسی نمی‌شود.

---

## D2 — publish عمومی معطل (🔴 · منشأ PN-003..012)

| فیلد | مقدار |
|---|---|
| فرضیهٔ اولیهٔ سند | DB ۲۶۵MB در repo — **رد شد با شاهد** (db/custom.db هرگز در git نبود؛ gitignored از P6549) |
| ریشهٔ واقعی | تورم دوبارهٔ بستهٔ استقرار: public/deliver (۵۹۴MB، دوبار) + upload/dataset-backups (۳۸۸MB) — همان الگوی P6528 با فهرست‌های تازه |
| اصلاح GLM | تحویل‌ها → `deliver-store/` (خارج از public) + مسیر سرو `/deliver/[...path]` + excludes/پاک‌سازی بیلد — بستهٔ شبیه‌سازی‌شده: **tar.gz ۹۵MB** (زیر آستانهٔ موفق تاریخی ~۱۰۰MB) |
| کنش باقی‌مانده | **انتشار از پنل مالک** (دکمهٔ Publish — راهنما: `docs/PUBLISH-TROUBLESHOOTING.md`) |
| وضعیت | ⏳ در انتظار کنش مالک — برای نخستین‌بار از PN-007 بسته زیر سقف خط لوله است |

## D3 — کد مستر در تاریخچهٔ کامیت (🟠 · منشأ PN-008)

| فیلد | مقدار |
|---|---|
| تصمیم | **بستن با احترام** — «کد تغییر نمی‌کند»: بازنویسی تاریخچه (گزینه الف) انجام نمی‌شود |
| نظر مالک | ریسک پذیرفته شد (جلسهٔ ۰۱۸) |
| قید ۱ — خصوصی | مخزن GitHub خصوصی است: پروب ناشناس → 403 (راستی‌آزمایی ۱۴۰۵/۰۷/۱۸ + گارد خودکار هر ۶ ساعت) |
| قید ۲ — رمزنگاری | escrow لایهٔ سوم با **scrypt سختِ حافظه** (N=2^15, r=8, p=1 — هر تلاش بروت‌فورس ~۱۰۰ms و پرهزینهٔ RAM) + AES-256-GCM — `scripts/pn012/escrow-manager.ts` |
| قید ۳ — پایش | گارد `privacy-guard` در Worker: هر ۶ ساعت پروب ناشناس api.github.com — اگر روزی ۲۰۰ برگرداند (عمومی شدن)، هشدار فوری `INFRA_ALERT` در AuditLog |
| وضعیت | ✅ بسته با احترام — سه قید برقرار و خودپایا |

## D4 — تصمیم LFS برای شاخهٔ main آینه (🟡 · منشأ PN-010)

| فیلد | مقدار |
|---|---|
| تصمیم | **تعویق آگاهانه** — با محرک‌های عددی و پایش خودکار ساعتی |
| محرک ۱ | db/custom.db > **500MB** — زنده: ۲۵۷٫۵MB (سبز) |
| محرک ۲ | مجموع بسته‌های بقا > **1GB** — زنده: ۳۲۰۱٫۸MB (**🔴 از نخستین سنجش فعال** — ۱۴۰۵/۰۷/۱۸ ۱۶:۱۲Z) |
| محرک ۳ | فضای آزاد دیسک < **۱۵٪** — زنده: ~۳۳٪ (سبز) |
| پایش | گارد `size-guard` در Worker: هر ساعت + هشدار خودکار `INFRA_ALERT` در AuditLog (تأیید زنده: رد ثبت شد) |
| گزینه‌های مالک | الف) هرس بسته‌های کهنهٔ زنجیره (نگه‌داشتن N آخر) · ب) ارتقای ظرفیت (D1) · ج) LFS/آرشیو برون‌پلتفرمی |
| توصیهٔ GLM | الف+ب — هرس نگه‌دارنده + ارتقا هنگام فعال‌شدن محرک دیسک |
| وضعیت | ⏳ تعویق‌شده با پایش فعال — **محرک ۲ هم‌اکنون فعال است و نیازمند تصمیم مالک** |

## سازوکار مرور

- گاردها وضعیت خود را در `upload/.runtime/runtime-status.json` می‌نویسند (قابل مشاهده در پانل متریک OWNER: `/api/v1/runtime/metrics`).
- هشدارها با `action=INFRA_ALERT` در AuditLog ثبت می‌شوند (append-only — قاعدهٔ ۱۴).
- فعال‌شدن هر محرک = مالک این دفتر را با تصمیم تازه تکمیل می‌کند (ورودی جدید، بدون حذف تاریخ).
