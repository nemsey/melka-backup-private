# راهنمای بوت پلتفرم ملکا — برای مالک
**ملکا-شورا-ن۰۰۶-۱۴۰۵ · BLOCK 1.4 · تاریخ: ۱۴۰۵/۰۷/۱۶**

---

## چه اتفاقی افتاده است؟

از جلسهٔ ۰۰۶ به بعد، دستور `bun run dev` دیگر مستقیماً حالت توسعهٔ سنگین راه نمی‌اندازد؛ بلکه یک **دروازهٔ حالت‌دار** شده است:

| حالت | شرط | نتیجه | مصرف RAM |
|---|---|---|---|
| **پیش‌فرض (توصیه‌شده)** | هیچ تغییری لازم نیست | سرور production پایدار + گارد خوددرمان + نگهبان ری‌استارت خودکار | **~۲۰۰-۳۰۰MB** |
| توسعهٔ واقعی | فقط روی ماشین توسعهٔ محلی با `MELK_DEV_MODE=1` | next dev کامل (Turbopack) | ~۲.۹GB |

یعنی: **اگر کانتینر ری‌استارت شود، دیگر به حالت ۲.۹ گیگابایتی برنمی‌گردد** — همان چیزی که سه بار باعث تخریب محیط شده بود.

**✅ نتیجهٔ عملی: از این پس لازم نیست کاری انجام دهید.** همان دستور قبلی پلتفرم (`bun run dev`) اکنون خودش production را بالا می‌آورد. این سند فقط برای شفافیت و اختیارهای پیشرفته است.

---

## گام‌های اختیاری برای مالک (در صورت تمایل)

### گام ۱ — بررسی سلامت (هیچ تغییری لازم نیست)
آدرس `/api/version` را باز کنید. باید ببینید:
```json
{ "env": "production", "gitSha": "<آخرین کد>", "buildId": "<آخرین کد>-..." }
```

### گام ۲ — اگر خواستید دستور بوت را در پنل Z.AI عوض کنید (اختیاری)
اگر پنل اجازهٔ ویرایش «دستور اجرا» را می‌دهد، می‌توانید به‌جای `bun run dev` این را بگذارید:
```
bash start.sh
```
این مسیر همان نتیجه را می‌دهد (دروازهٔ production + گارد بازیابی + بیلد در صورت نبود) — تنها تفاوت: حتی دروازهٔ حالت‌دار هم دور زده می‌شود و همیشه production است.

### گام ۳ — اگر روزی خواستید روی سرور توسعه بدهید (توصیه نمی‌شود)
متغیر محیطی `MELK_DEV_MODE=1` را تنظیم کنید یا از میان‌بر `bun run dev:real` استفاده کنید. پس از اتمام کار، حتماً به حالت پیش‌فرض برگردید.

## سازوکارهای محافظ نصب‌شده (خودکار — بدون نیاز به اقدام)

1. **گارد خوددرمان (recovery-guard):** در هر بوت، سلامت پایگاه داده وارسی می‌شود؛ اگر تخریب ساختاری دیده شود (هش کد مدیر پاک شده یا گراف صفر شده)، خودش از بستهٔ بقا بازیابی می‌کند. ضدحلقهٔ ۱۰ دقیقه‌ای دارد.
2. **نگهبان ری‌استارت (watchdog):** اگر سرور کرش کند، پس از ۵ ثانیه دوباره بالا می‌آید. توقف رسمی فقط با فایل `.prod-stop`.
3. **بیلد در صورت نبود:** اگر خروجی production وجود نداشته باشد، در همان بوت ساخته می‌شود.

## خلاصهٔ یک‌خطی

> **هیچ اقدامی لازم نیست؛ همه‌چیز از مسیر `bun run dev` به production پایدار تغییر مسیر داده شده است.** این سند صرفاً برای آگاهی و گزینه‌های اختیاری است.
