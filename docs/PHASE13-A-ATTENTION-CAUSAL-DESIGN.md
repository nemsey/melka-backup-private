## فصل ۱ — فلسفه و انگیزه

### ۱.۱ — مغز فعلی: یازده موتورِ تکی‌اندیش

مغز ملکا امروز یازده موتور دارد که هر یک پرسش خود را پاسخ می‌دهد:

| # | موتور | پرسش | خانهٔ کد |
|---|---|---|---|
| ۱ | Outcome (پیامد) | «چه شد؟» | p7-core |
| ۲ | Evaluation (ارزیابی) | «چقدر دقیق بودیم؟» | p7-core |
| ۳ | Learning (یادگیری) | «چه وزنی بگیریم؟» | p7-core |
| ۴ | Drift (رانش) | «دنیا عوض شد؟» | p7-core |
| ۵ | Decision (تصمیم) | «چه کنیم؟» | p8-core |
| ۶ | ActionPlanner (برنامه) | «چطور اجرا کنیم؟» | p8-core |
| ۷ | Safety (ایمنی) | «مجاز است؟» | p8-core |
| ۸ | Governance (حاکمیت) | «قاعده رعایت شد؟» | p9-core |
| ۹ | PolicyEvaluation (سیاست) | «سیاست کار کرد؟» | p9-core |
| ۱۰ | SelfDiagnosis (خودآگاهی) | «خودم سالمم؟» | p10-core |
| ۱۱ | SelfRepair (خودترمیمی) | «خودم را ترمیم کنم؟» | p11-core |

این یازده موتور «فرا-عملکردی» هستند: هر یک روی ورودیِ از-پیش-موجود کار
می‌کند. اما دو توانایی پایه‌ای شناختی غایب‌اند — توانایی‌هایی که حتی کودک
پنج‌ساله دارد و این سیستم ندارد:

۱. **توجه (Attention):** با ۲۷٬۷۷۷ آگهی و ۹۷۷ هشدار، کدام ۱۰ مورد ارزش
   فکر کردن دارند؟ سیستم فعلی همه را «برابر» می‌بیند؛ یعنی هیچ‌را نمی‌بیند.
۲. **علّیت (Causality):** «آگهی‌های با تصویر ۸۰٪ معامله می‌شوند» — اما
   آیا تصویر *علت* است یا فقط *همراه*؟ سیستم فعلی فقط همبستگی می‌فهمد.

### ۱.۲ — چرا این دو، پایه‌اند؟

فازهای ۱۳-ب و ۱۳-ج (طبق نقشهٔ سه‌فازی فرا-ذهن) روی همین دو سوار می‌شوند:

```
فاز ۱۳-الف (این سند)          فاز ۱۳-ب                فاز ۱۳-ج
─────────────────         ─────────────────      ─────────────────
موتور ۱۲: توجه      ──►    پادواقع (L3)        روایت (Narrative)
موتور ۱۳: علّیت     ──►    شبیه‌سازی سناریو     گزارش مالک
گراف علّی پایدار    ──►    what-if روی گراف     خلاصهٔ علّی وقایع
بودجهٔ توجه         ──►    اولویت شبیه‌سازی     انتخاب روایت برتر
```

بدون توجه، پادواقع روی «همه‌چیز» اجرا می‌شود (غیرممکن). بدون علّیت،
پادواقع «اگر چه را تغییر می‌دادم؟» را نمی‌تواند بپرسد. این فاز دو
پایه را می‌گذارد — با کوچک‌ترین ردپای ممکن.

### ۱.۳ — سه اصل حداقلی (مصوبهٔ شورا)

۱. **صفر migration تهاجمی:** تنها تغییر schema یک جدول افزودنی
   `CausalEdgeRecord` است (قانون ۸: صفر DROP · صفر DELETE · صفر تغییر نوع
   ستون موجود). ۵۹ جدول موجود دست نمی‌خورند — می‌شوند ۶۰.
۲. **صفر LLM call در تولید:** موتورها ریاضیات خالص‌اند (همبستگی،
   topological sort، وزن‌دهی خطی) — همان مرز هوش مصنوعی گارد DIg-SEC-003.
۳. **صفر auto-execute:** خروجی موتورها «امتیاز + دلیل + گراف» است؛ اجرا
   همچنان انسانی است (عین قید فاز ۸ — سایه صفر-اجرا).

### ۱.۴ — آنچه این فاز نیست

- سیستم توصیهٔ خودکار نیست — خروجی «۱۰ مورد برتر + دلیل» برای *مشاهدهٔ*
  مالک است، نه کنش خودکار.
- استنتاج علّی جامع نیست — L1+L2 روی مدل خطی با دادهٔ مشاهداتی؛ ادعای
  کشف «همهٔ علّت‌ها» نداریم (محدودیت‌ها در فصل ۱۰ صادقانه).
- جایگزین قهرمان/چالشگر نیست — موتور علّیت *کنار* چرخهٔ نسخه‌بندی
  می‌نشیند، نه به‌جای آن.

### ۲.۲ — قواعد معماری حمل‌شده

۱. **خالص‌نویسی (Purity):** موتورهای ۱۲ و ۱۳ صفر وابستگی به DB/سیستم
   فایل دارند — ورودی داده، خروجی داده، خطای صریح. ماندگاری در لایهٔ
   جدا (causal-graph-store) — عین الگوی p7-core که تست‌ها با جفت‌های
   تزریقی کار می‌کنند.
۲. **مرز مخزن:** دسترسی DB فقط از سرویس نازک store — گارد
   audit-repository-boundary از فاز ۳ این را enforcement می‌کند.
۳. **فایل تازه، صفر دست‌کاری موجود:** چهار فایل تازه در
   core/intelligence/؛ هیچ فایل موجودی در این فاز تغییر معنایی
   نمی‌خورد (تنها: افزودن مدل Prisma + بروزرسانی شمارندهٔ تستِ خود
   پنجرهٔ postgres-compat از ۵۹ به ۶۰ — تستِ خودِ همین پیاده‌سازی).
۴. **شاهد‌محوری:** هر موتور خروجی JSON شاهد با روایت فارسی برمی‌گرداند
   (عین قواعد فازهای ۷-۱۱).

### ۲.۳ — جریان دادهٔ موتور توجه

```
PropertyRecord/OpportunityAlert/… (منابع)
        │  نگاشت به AttentionItem (اسکریپت شاهد — نه درون موتور)

        │  ۱) تازگی: واپاشی نمایی بر سن رویداد

        │  ۳) تطابق: هم‌پوشانی دامنه‌ها با اولویت مالک
        │  ۴) هزینه: وارونهٔ هزینهٔ پردازش
        ▼

```

### ۲.۴ — جریان دادهٔ موتور علّیت

```
دادهٔ تاریخی (ویژگی‌ها + پیامد معامله)
        │
        ▼

```

## فصل ۳ — موتور توجه: قرارداد

### ۳.۱ — ورودی خام (AttentionItem)

```typescript
export interface AttentionItem {
  /** شناسهٔ پایدار مورد (کد ملک، شناسهٔ هشدار، …) */
  itemId: string;
  /** زمان رویداد/ثبت — ISO 8601 (برای تازگی) */
  occurredAt?: string;
  /** اثر مالی بالقوه — مقیاس دلخواه (تومان یا نرمال) */
  impactValue?: number;
  /** احتمال وقوع/موفقیت 0..1 (از موتور پیش‌بینی یا تخمین ساده) */
  probability?: number;
  /** دامنه‌ها/برچسب‌ها برای تطابق با اولویت مالک */
  domains?: readonly string[];
  /** هزینهٔ پردازش 0..1 — بالاتر = گران‌تر (کارشناس مشغول؟) */
  costFactor?: number;
}
```

قواعد: همهٔ فیلدها اختیاری جز `itemId` — غیبت یعنی «نامعلوم»، نه «صفر»؛
موتور با پیش‌فرض‌های صادقانه (فصل ۴.۵) کار می‌کند و دلیلِ خود را می‌گوید.

### ۳.۲ — اولویت مالک (AttentionPriority)

```typescript
export interface AttentionPriority {
  /** دامنه‌های موردعلاقهٔ مالک (مثل AREA:منطقة-۲، TILE:market-index) */
  domains: readonly string[];
  /** وزن‌ها — مجموع باید ۱ باشد (اعتبارسنجی fail-loud) */
  weightFreshness?: number;   // پیش‌فرض ۰٫۲۵
  weightImpact?: number;      // پیش‌فرض ۰٫۳۵
  weightAlignment?: number;   // پیش‌فرض ۰٫۲۵
  weightCost?: number;        // پیش‌فرض ۰٫۱۵
  /** مرجع «اکنون» برای تازگی (تست تعیین‌پذیری) */
  now?: Date;
  /** نیم‌عمر تازگی به ساعت — پیش‌فرض ۴۸ */
  freshnessHalfLifeHours?: number;
}
```

### ۳.۳ — خروجی (AttentionScore)

```typescript
export interface AttentionScore {
  itemId: string;
  freshness: number;       // 0..1 — ۱ = همین حالا
  potentialImpact: number; // 0..1 — نرمال‌شده درون دسته
  alignment: number;       // 0..1 — ۱ = هم‌دامنهٔ کامل
  costFactor: number;      // 0..1 — ۱ = ارزان (وارونه‌سازی در موتور)
  total: number;           // 0..1 — میانگین وزنی چهار مؤلفه
  reason: string;          // روایت فارسی انتخاب/رد
}
```

`reason` الزامی است — «۱۰ آگهی برتر با دلیل» وعدهٔ سفارش است؛ ردیف بدون
دلیل، نقض قرارداد است (گارد audit-meta-mind رشتهٔ خالی را رد می‌کند).

### ۳.۴ — رابط موتور

```typescript
export class AttentionEngine {
  constructor(priority: AttentionPriority);
  /** رتبه‌بندی + برش بودجه — مرتب‌شدهٔ نزولی بر total، تعادل‌شکن: itemId */
  rank(items: readonly AttentionItem[], budget: number): AttentionScore[];
  /** روایت کامل یک مورد (از آخرین رتبه یا بازمحاسبه) */
  explain(itemId: string): string;
  /** امتیاز کامل بدون برش — برای تحلیل/تست */
  scoreAll(items: readonly AttentionItem[]): AttentionScore[];
}
```

قواعد رفتاری:
- `budget ≤ 0` ⇒ خروجی خالی (بودجهٔ صفر = بی‌توجهی، نه همه‌چیز).
- `items` خالی ⇒ خروجی خالی — بدون خطا.
- ورودی‌های تکراری itemId ⇒ `ATTENTION_DUPLICATE_ITEM` (خطای صریح —
  صفر سکوت).
- خروجی `rank` همیشه ≤ budget و مرتب بر total نزولی.

## فصل ۴ — موتور توجه: الگوریتم

### ۴.۱ — مؤلفهٔ ۱: تازگی (Freshness)

واراپاشی نمایی بر سن رویداد:

```
age_h = (now − occurredAt) / 3600_000
freshness = 2^(−age_h / halfLife)        // halfLife پیش‌فرض ۴۸h
```

- «امروز» (۰ ساعت) = ۱٫۰ · «دیروز» (۲۴h) ≈ ۰٫۷۱ · «هفتهٔ پیش» (۱۶۸h) ≈ ۰٫۰۸۸.
- غیبت `occurredAt` ⇒ پیش‌فرض ۰٫۱ (کهنه-فرض صادقانه — نامعلوم را قدیمی
  می‌گیریم، نه تازه؛ خطای محافظه‌کارانه).

### ۴.۲ — مؤلفهٔ ۲: اثر بالقوه (PotentialImpact)

```
raw = impactValue × probability          // ارزش موردنظر × شانس
potentialImpact = raw / max(raw_همه)      // نرمال‌سازی بیشینهٔ دسته
```

- نرمال‌سازی «درون-دسته» (نه مطلق): برترین مورد دسته همیشه ۱ می‌گیرد —
  رتبه‌بندی نسبی است، ادعای مطلق نیست.
- غیبت هر مؤلفه ⇒ ضرب در مقدایر خنثی (impactValue غایب ⇒ ۰ — بدون اثر
  مالی، ادعای اثر نداریم؛ probability غایب ⇒ ۰٫۵ — بی‌طرف).

### ۴.۳ — مؤلفهٔ ۳: تطابق (Alignment)

```
overlap = |item.domains ∩ priority.domains|
alignment = overlap / max(1, min(|item.domains|, |priority.domains|))
```

مخرجِ «کوچک‌ترین مجموعه» — یعنی پوشش کامل مجموعهٔ کوچک‌تر = ۱؛ جریمهٔ
فهرست‌بلند-کردن مصنوعی وجود ندارد (دامنهٔ بی‌ربط امتیاز نمی‌آورد).

### ۴.۴ — مؤلفهٔ ۴: هزینهٔ توجه (CostFactor)

```
costFactor = 1 − clamp(rawCost, 0, 1)    // وارونه: ارزان = ۱
```

منطق: «کارشناس در دسترس است؟» — موردِ نیازمند کارشناسِ مشغول، گران
است؛ امتیازش سقف می‌خورد. غیبت ⇒ ۰٫۸ (کمی گران — پیش‌فرض محافظه‌کار).

### ۴.۵ — جدول پیش‌فرض‌های صادقانه

| فیلد غایب | پیش‌فرض | فلسفه |
|---|---|---|
| occurredAt | freshness = ۰٫۱ | نامعلوم = قدیمی |
| impactValue | ۰ | بدون اثر ادعا نمی‌کنیم |
| probability | ۰٫۵ | بی‌طرف |
| domains | [] ⇒ alignment = ۰ | بدون دامنه، تطابقی نیست |
| costFactor(raw) | ۰٫۲ | کمی گران |

### ۴.۶ — امتیاز کل و روایت

```
total = wF·freshness + wI·potentialImpact + wA·alignment + wC·costFactor
```

اعتبارسنجی: مجموع وزن‌ها = ۱ ± ۰٫۰۰۰۱ — وگرنه `ATTENTION_WEIGHTS`
(خطای صریح).

`reason` — قالب روایت (نمونهٔ واقعی):

> «آگهی ۴۰۸۳۴: تازگی ۰٫۹۲ (امروز) · اثر ۱٫۰۰ (برترین دسته) · تطابق ۰٫۵۰
> (AREA:منطقة-۲) · هزینه ۰٫۸۰ — امتیاز ۰٫۸۶ — رتبهٔ ۱ از ۲۷٬۷۷۷»

ردِ خارج از بودجه (explain برای موردِ بریده‌شده):

> «آگهی ۳۹۰۳۲: امتیاز ۰٫۴۱ — زیر خط بودجهٔ ۱۰ (رتبهٔ ۱۴)؛ عامل غالب:
> تازگی ۰٫۰۹ (۱۰ روز پیش)»

### ۴.۷ — پیچیدگی و مقیاس

O(n·d) برای n مورد و d دامنه — ۲۷٬۷۷۷ آگهی در < ۵۰ms (تک‌گذر، بدون
تخصیص مکرر). مرتب‌سازی پایدار O(n log n). حافظه: O(n).

## فصل ۵ — موتور علّیت: قرارداد

### ۵.۱ — دادهٔ مشاهده‌ای (CausalDataPoint)

```typescript
export interface CausalDataPoint {
  /** ویژگی‌های عددی (قیمت متر، متراژ، اتاق، سن بنا، …) */
  features: Readonly<Record<string, number>>;
  /** پیامد عددی (0/1 معامله‌شدن یا مقدار پیوسته) */
  outcome: number;
}
```

### ۵.۲ — یال و گراف

```typescript
export interface CausalEdge {
  from: string;             // ویژگی مبدأ
  to: string;               // ویژگی مقصد یا «outcome»
  coefficient: number;      // −1..+1 — جهت و اندازهٔ اثر
  confidence: number;       // 0..1 — کف ۰٫۶ برای پذیرش
  method: "L1" | "L2";      // سطح Pearl مولد یال
  evidence: string;         // شاهد فارسی (n، r، نحوهٔ محاسبه)
}

export interface CausalGraph {
  nodes: readonly string[];         // شامل «outcome»
  edges: readonly CausalEdge[];
  sampleSize: number;
  builtAt: string;
  dagVerified: boolean;             // مهر اعتبارسنجی Kahn
}
```

### ۵.۳ — رابط موتور

```typescript
export class CausalEngine {
  constructor(opts?: { confidenceFloor?: number; minSamples?: number });
  /** L1: ساخت گراف از داده + اعتبارسنجی DAG — cycle ⇒ CAUSAL_CYCLE_DETECTED */
  buildGraph(data: readonly CausalDataPoint[], featureOrder?: readonly string[]): CausalGraph;
  /** L2: اثر مداخله do(feature += delta) بر outcome — جمع مسیرهای DAG */
  intervene(graph: CausalGraph, action: { feature: string; delta: number }): CausalEffect;
  /** یافتن علل یک اثر — مرتب بر |ضریب| */
  findCause(graph: CausalGraph, effect: string): CausalEdge[];
  /** اعتبارسنجی مستقل DAG (عمومی — برای گارد/تست) */
  assertDag(nodes: readonly string[], edges: readonly {from: string; to: string}[]): void;
}
```

### ۵.۴ — دو گیت حیاتی (قوانین ۷ و سفارش §۳.۲)

۱. **DAG اجباری:** هر ساخت/بارگذاری گراف از الگوریتم Kahn عبور
   می‌کند؛ یافتن cycle ⇒ پرتاب `CAUSAL_CYCLE_DETECTED` با فهرست یال‌های
   درگیر — توقف فوری، صفر ادامه (قانون ۷).
۲. **کف اطمینان:** یال با confidence < ۰٫۶ در `buildGraph` رد می‌شود
   (پیش‌فرض؛ قابل‌تنظیم فقط با گواهی صریح تست). کف از DB هم در گارد
   `audit-causal-validity` enforcement می‌شود.

## فصل ۶ — موتور علّیت: الگوریتم (Pearl سه‌سطح)

### ۶.۱ — چرا سه سطح؟

| سطح | پرسش | ابزار | این فاز |
|---|---|---|---|
| L1 | «چه چیزی هم‌بسته است؟» | P(Y|X) — همبستگی | ✅ پیاده |
| L2 | «اگر مداخله کنیم؟» | P(Y|do(X)) — جراحی گراف | ✅ پیاده |
| L3 | «اگر نمی‌کردیم چه می‌شد؟» | P(Y_x|x′,y′) — پادواقع | فاز ۱۳-ب |

### ۶.۲ — L1: برآورد یال‌ها (Association)

برای هر جفت مرتب (A→B) در ترتیب ویژگی‌ها و هر ویژگی→outcome:

```
r = Pearson(A, B)                     // ضریب همبستگی
n = تعداد جفت‌های کامل
t = |r|·√((n−2)/(1−r²))              // آمارهٔ t
confidence = clamp( (1 − e^{−t/3}) · √(min(n,N₀)/N₀), 0, 1 )
   // N₀ = ۳۰ — نمونهٔ کافی ⇒ توقف رشد اطمینان؛ نمونهٔ کم ⇒ جریمه
```

- `method: "L1"` روی همهٔ یال‌های ساخته‌شده در این مرحله.
- |r| < ۰٫۰۵ یا confidence < کف ⇒ یال ساخته نمی‌شود.
- `evidence`: «Pearson r=−۰٫۲۱ روی n=۷۶۸ جفت — بررسی هم‌بستگی L1».

### ۶.۳ — ترتیب ویژگی‌ها (ضمانت ساختاری DAG)

همبستگی متقارن است؛ گراف جهت‌دار می‌خواهد. راه‌حل صادقانه: **ترتیب
علّی پیشینی** (پیش‌فرض منطقی: ویژگی‌های ذاتی ملک → ویژگی‌های نمایش →
پیامد). یال فقط از «جلوتر در ترتیب» به «عقب‌تر» مجاز است:

```
featureOrder = [price, meterage, rooms, buildYear, area, hasImage, …, "outcome"]
```

یعنی A→B فقط اگر index(A) < index(B). این + Kahn = DAG تضمینی دو-لایه.
`featureOrder` اختیاری است؛ غیبت ⇒ ترتیب حروفی فهرست ویژگی‌ها + outcome
آخر — مستند در evidence گراف.

### ۶.۴ — L2: مداخله (Intervention)

مدل خطی SCM تقریبی: هر یال ضریب β. اثر do(X += δ) بر outcome:

```
totalEffect = δ × Σ_{مسیرهای X→…→outcome} (Π β_یال‌های مسیر)
directEffect = δ × β_{X→outcome}   (اگر یال مستقیم هست؛ وگرنه ۰)
```

شمارش مسیرها با DFS روی DAG (سقف ایمن ۱۰۰۰ مسیر — توقف صریح
`CAUSAL_PATH_OVERFLOW` اگر عبور کرد). `evidence`:

> «مداخلهٔ do(hasImage += 1): اثر کل +۰٫۳۱ روی احتمال معامله (۲ مسیر:
> مستقیم ۰٫۲۲ + ازمسیر قیمت ۰٫۰۹) — مدل خطی SCM، سطح L2»

### ۶.۵ — findCause

یال‌های ورودی به effect، مرتب نزولی بر |coefficient| — خروجی آرایه؛
دلیل علّیِ «برترین» مرتباً در evidence یال مهر شده است.

### ۶.۶ — محدودیت‌های صادقانهٔ الگوریتم

- **مدل خطی:** اثرهای تعاملی (مثل «تصویر فقط برای آپارتمان») دیده
  نمی‌شوند — فاز ۱۳-ب با شبیه‌سازیِ غیرخطی روی همین گراف.
- **مخلوط‌شدگی (Confounding):** ترتیب علّی پیشینی فرض است؛ متغیر مخلوط
  نادیده‌شده ممکن است ضریب را متورم کند — evidence هر یال شامل n و r
  است تا مالک خودش قضاوت کند.
- **دادهٔ مشاهداتی:** L2 با فرضِ گراف درست برآورد می‌شود؛ ادعای
  «آزمایش تصادفی» نداریم (صداقت عین جدول ۲.۲ سفارش).

## فصل ۷ — گراف علّی: ساختار دادهٔ پایدار

### ۷.۱ — مدل Prisma (افزودنی — قانون ۸)

```prisma
/// PN-023-A (فاز ۱۳-الف) — یال گراف علّی پایدار (موتور ۱۳).
model CausalEdgeRecord {
  id          String   @id @default(cuid())
  fromFeature String
  toFeature   String
  /// −1..+1 — جهت و اندازهٔ اثر (مدل خطی SCM)
  coefficient Float
  /// 0..1 — کف پذیرش ۰٫۶ (گارد audit-causal-validity)
  confidence  Float
  /// L1 | L2 — سطح Pearl مولد
  method      String
  evidence    String
  createdAt   DateTime @default(now())
  @@unique([fromFeature, toFeature, method])
  @@index([toFeature])
}
```

- **صفر تغییر در ۵۹ جدول موجود** — فقط یک model جدید؛ هیچ DROP/DELETE/
  تغییر نوعی رخ نمی‌دهد (قانون ۸).
- twin schema (schema.postgres.prisma) همان model را می‌گیرد — گارد
  postgres-compat توازن ۶۰=۶۰ را enforcement می‌کند (وگرنه CI قرمز).

### ۷.۲ — سرویس ماندگاری (src/lib/services/causal-graph-store.ts — لایهٔ سرویس)

```typescript
export async function saveGraph(graph: CausalGraph): Promise<{ saved: number }>;
//   upsert بر کلید یکتا (fromFeature, toFeature, method) — idempotent
export async function loadGraph(): Promise<CausalGraph | null>;
//   آخرین snapshot از DB + assertDag پیش از بازگشت (قانون ۷ در خواندن هم)
export async function graphStats(): Promise<{ edges: number; nodes: number; avgConfidence: number; lastSavedAt: string | null }>;
```

قواعد: `saveGraph` پیش از نوشتن `assertDag` می‌گیرد — گراف چرخه‌ای
هرگز وارد DB نمی‌شود؛ `loadGraph` پس از خواندن دوباره DAG را تأیید
می‌کند (دست‌کاری بیرونی DB را هم می‌گیرد).

### ۷.۳ — چرخهٔ عمر گراف

ساخت (اسکریپت شاهد از دادهٔ واقعی) ⇒ assertDag ⇒ ذخیره (upsert) ⇒
خواندن (تست/گارد) ⇒ بازسازی دوره‌ای (فاز ۱۳-ب در Worker — خارج از این
فاز). هر بازسازی history را حذف نمی‌کند — upsert idempotent است؛ تاریخ
`createdAt` اولین ساخت هر یال را نگه می‌دارد.
