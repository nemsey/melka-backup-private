# قرارداد متادیتای حافظه (Memory Metadata Contract) — PHASE 5

**نسخه سند:** 1.0 · **وضعیت:** مصوب برای پیاده‌سازی P5-02 · **قاعده حاکم:** قرارداد v1 موتورها دست‌نخورده؛ همه چیز افزودنی

---

## ۱. هدف

هر رکورد حافظه باید بتواند «مشخصات ساختاری» خود را حمل کند تا موتور بازیابی بتواند **پیش از جستجو** دامنه را محدود کند (فقط این ایجنت / فقط این منطقه / فقط این بازه زمانی) و رتبه‌بند بتواند بر اساس اهمیت/اعتماد/تازگی امتیاز دهد. این قرارداد **صفر Migration** است: متادیتا در همان فیلد `metadata?: Record<string, unknown>` رکورد PHASE 4 (قالب ذخیره‌سازی JSONL/Map موجود) با کلیدهای قراردادی ذخیره می‌شود و رکوردهای قدیمی (بدون متادیتا) با «مقادیر پیش‌فرض حل‌شده» پوشش داده می‌شوند.

## ۲. تعریف نوع کامل (TypeScript)

```typescript
/**
 * متادیتای ساختاری هر حافظه — قرارداد PHASE 5.
 * ذخیره‌سازی: داخل MemoryRecord.metadata با همین کلیدها (صفر تغییر قالب ذخیره‌سازی).
 * رکوردهای قدیمی: نبود کلید = مقدار پیش‌فرض حل‌شده (بند ۴).
 */
export interface MemoryMetadata {
  // ---------- شناسه‌ها ----------
  /** شناسه ایجنت مالک مشاهده — پیش‌فرض حل‌شده: null (نامشخص) */
  agentId?: string;
  /** شناسه کاشی — منبع حقیقت: همیشه از بدنه رکورد (record.tileId) گرفته می‌شود، نه از متادیتا */
  tileId?: string;
  /** دامنه معنایی — مثلاً: PERSONAL، PRICE، LOCATION، COMMUNITY_MGMT، CHURN */
  domain?: string;

  // ---------- مکان ----------
  city?: string;        // مثلاً: "تبریز"
  area?: string;        // مثلاً: "ولیعصر"، "لیل"، "ائل‌گلی"
  district?: string;    // محله‌های ریزتر

  // ---------- ملک ----------
  propertyType?: string; // apartment | villa | land | ...
  tradeType?: string;    // buy | sell | rent | ...

  // ---------- زمان ----------
  /**
   * زمان منطقی رویداد — پیش‌فرض حل‌شده: record.createdAt (ISO 8601).
   * متمایز از createdAt ثبت فنی: رویداد می‌تواند دیرتر ثبت شده باشد.
   */
  eventTime?: string;   // ISO 8601

  // ---------- منبع ----------
  source: MemorySource;
  /** شناسه منبع اصلی — مثلاً شناسه بازخورد، شناسه رویداد آرم */
  sourceRef?: string;

  // ---------- کیفیت ----------
  confidence: number;   // 0..1 — پیش‌فرض حل‌شده: 0.5 (نامشخص)
  importance: number;   // 0..1 — پیش‌فرض حل‌شده: 0.5 (نامشخص)

  // ---------- چند-کاربری ----------
  /** آماده برای آینده — فعلاً همیشه undefined (تک-کاربری) */
  tenantId?: string;

  // ---------- اعتبار زمانی ----------
  validFrom?: string;   // ISO 8601
  validUntil?: string;  // ISO 8601
}

export type MemorySource =
  | "user_feedback"      // بازخورد صریح کاربر
  | "insight_generated"  // حاصل بینش ایجنت
  | "outcome"            // نتیجه واقعی (مثلاً نتیجه پیش‌بینی)
  | "external";          // منبع بیرونی (API، همگام‌سازی)

/**
 * فیلتر پیش‌از-جستجو — همه فیلدهای اختیاری؛ نبود = بدون محدودیت آن بعد.
 * تطبیق: تساوی دقیق رشته‌ای (بعد از نرمال‌سازی فارسیِ همان فیلد در حل‌کننده).
 */
export interface MetadataFilter {
  agentId?: string;
  tileId?: string;
  city?: string;
  area?: string;
  propertyType?: string;
  tradeType?: string;
  fromDate?: string;      // ISO — eventTime >= fromDate (پیش‌فرض حل‌شده: createdAt)
  toDate?: string;        // ISO — eventTime <= toDate
  minConfidence?: number; // confidence >= minConfidence
  source?: string[];      // عضویت در فهرست (OR)
}
```

> انحراف صادقانه نسبت به پیش‌نویس دستور: `eventTime` و `fromDate/toDate` از `Date` به `string` ISO 8601 تغییر یافت — هم‌راستا با قرارداد حافظه PHASE 3/4 (`createdAt: string`) تا سریال‌پذیری JSON و مقایسه پایدار رشته‌ای حفظ شود. **هیچ دیتای تاریخ در این فاز ساخته نمی‌شود؛ رکوردهای موجود با createdAt پوشش داده می‌شوند.**

## ۳. قواعد قرارداد

1. **`tileId` منبع حقیقت دوگانه نیست:** فیلتر/رتبه‌بند همیشه `record.tileId` بدنه را می‌خواند؛ مقدار داخل متادیتا صرفاً اطلاعاتی است.
2. **مقدار پیش‌فرض حل‌شده (بند ۴ تابع `resolveMetadata`) برای رکوردهای قدیمی** معنای «خنثی» دارد: `confidence=0.5`، `importance=0.5`، `eventTime=createdAt`، `source="external"` — یعنی رکورد قدیمی نه‌به‌طور خودکار ارتقا می‌یابد و نه حذف می‌شود؛ فقط با فیلترهای صریحِ سخت‌گیرانه‌تر (مثلاً `minConfidence > 0.5`) کنار گذاشته می‌شود.
3. **بازه‌های کیفیت مقیدند:** `confidence` و `importance` خارج از [0,1] → به نزدیک‌ترین مرز بریده می‌شوند (clamp).
4. **`source` تنها فیلد اجباری** در نوع است، اما حل‌کننده برای رکوردهای قدیمی `external` را جایگزین می‌کند (رکورد قدیمی «منبع اعلام‌نشده» دارد).
5. فیلتر `source?: string[]` منطق OR دارد؛ آرایه خالی = بدون محدودیت.

## ۴. حل‌کننده متادیتا (تابع خالص `resolveMetadata`)

ورودی: `MemoryRecord` — خروجی: `MemoryMetadata` حل‌شده با پیش‌فرض‌ها. نکات پیاده‌سازی:

- خواندن کلیدهای قراردادی از `record.metadata` با بررسی نوع (رشته/عدد محدود)؛ مقدار نامعتبر = پیش‌فرض.
- `tileId` همیشه از `record.tileId`؛ `eventTime` نامعتبر/ناموجود = `record.createdAt`.
- `confidence`/`importance`: عدد محدود → clamp به [0,1]؛ در غیر این صورت 0.5.
- `source` فقط اگر عضو مجموعه چهارگانه مجاز باشد پذیرفته می‌شود؛ وگرنه `"external"`.

## ۵. کاربرد در فروشگاه (افزودنی P5-02)

قابلیت اختیاری جدید روی درگاه `MemoryStore` (الگوی «قرارداد قابلیت اختیاری» — استاندارد اجباری PHASE 5):

```typescript
export interface MemoryStore {
  // ... پنج متد v1 عیناً دست‌نخورده ...
  /** PHASE 5 — قابلیت افزودنی اختیاری؛ پیاده‌سازی در InMemoryStore و FileSystemStore */
  queryWithFilter?(filter: MetadataFilter): Promise<MemoryRecord[]>;
}
```

- اختیاری بودن متد، سازگاری عقب‌وار کامل را تضمین می‌کند: هر پیاده‌سازی شخص ثالث از `MemoryStore` بدون این متد همچنان معتبر است (مصرف‌کننده با duck-typing بررسی می‌کند و در نبود آن به مسیر جایگزین محلی می‌رود).
- ترتیب خروجی: جدیدترین‌اول بر اساس `eventTime` حل‌شده (سازگار با `query` موجود که createdAt-نزولی است؛ در رکوردهای جدید دو زمان یکی است).

## ۶. مرزها و ممنوعیت‌ها

- صفر Prisma / صفر `@/lib/db` / صفر fetch / صفر React (ممیزی `--strict`).
- صفر Migration — متادیتا فقط در فیلد موجود `metadata` زندگی می‌کند.
- قرارداد v1 (`engines/memory.ts`) **دست نمی‌خورد**؛ `MemoryEntry` هفت فیلد خود را نگه می‌دارد و متادیتا هرگز به خروجی قراردادی `query` نشت نمی‌کند.
- `tenantId` در این فاز همیشه `undefined` است (آماده‌سازی آینده؛ هیچ منطقی آن را نمی‌نویسد/نمی‌خواند).
