# سیاست بازیابی ملکا (RECOVERY-POLICY) — دکترین رستاخیز نهایی (PN-042)

**پرونده:** PN-042 · جلسهٔ ۰۷۰ (۲۸ مهر ۱۴۰۵)
**وضعیت:** لازم‌الاجرا · **جایگزین کامل** رویه‌های P6548-Tier4، سپر عالی (PN-040) و قلاب‌های بوت قلعه (PN-041)
**فلسفه:** پایان چرخهٔ شکست — «ابزار نجات هرگز نباید در محیطِ ریست‌شونده زندگی کند»

---

## ۰) قانون مجری کور (Blind Executor)

از این پس هرگاه مالک دستور رستاخیز را به GLM بدهد، GLM مجاز نیست:

1. فایل `resurrect-ultimate.sh` را باز کند یا تحلیل کند؛
2. دستورات درون آن را تغییر دهد یا «بهتر» کند؛
3. نسخهٔ قدیمی را به‌جای اجرای فرمان بالا بیاورد؛
4. کد جدیدی بنویسد یا فایل‌ها را برای «تشخیص» بکاود.

GLM فقط دستور را در ترمینال اجرا می‌کند و منتظر پیام `✅ RESURRECTION COMPLETE` می‌ماند؛
سپس خروجی را گزارش می‌دهد. منطقِ نجات در گیت‌هاب است، نه در ذهنِ مدل.

## ۱) فرمان واحد مالک (پس از هر ریست)

> **کشف حیاتی PN-042-A (شورا-ن۰۷۹):** مخزن **خصوصی** است — raw گیت‌هاب بدون توکن **۴۰۴** می‌دهد.
> یک‌خطی ناشناس هرگز کار نمی‌کرد؛ فرمان صحیح (احرازشده):

```bash
set -a; . upload/.mirror/credentials.env; set +a
TOKEN=$(printf '%s' "$MIRROR_URL_AUTHED" | sed -n 's#https://[^:]*:\([^@]*\)@.*#\1#p')
curl -fsSL -H "Authorization: token $TOKEN" "https://raw.githubusercontent.com/nemsey/melka-backup-private/main/resurrect-ultimate.sh?t=$(date +%s)" | bash
```

- توکن در `upload/.mirror/credentials.env` (متغیر `MIRROR_URL_AUTHED` — بادوام، هر ریست جان می‌دهد) یا در remote های گیت.
- `?t=$(date +%s)` = عبور از کش ۵دقیقه‌ای raw (درس ۳ شورا-ن۰۷۹).
- **اثبات زنده (۲۰۲۶-۱۰-۱۹ ۰۸:۴۹): ✅ RESURRECTION COMPLETE در ۸۹ ثانیه** — dfffdd70 → 2d0274ce = HEAD.

- این یک‌خطی **تنها** مسیر رسمی بازیابی کامل است (کد + داده + راز + بیلد + بوت + تأیید).
- منبع: `main` گیت‌هاب `nemsey/melka-backup-private` — همیشه آخرین نسخهٔ سالم (قانون ۰۳۱ پوش-فوری).
- پیام موفقیت فقط با شاهد زنده چاپ می‌شود: `/api/version` باید `gitSha == HEAD` پس از fetch بدهد؛
  در غیر این صورت `❌ RESURRECTION FAILED` و خروج غیرصفر — **هیچ موفقیت کاذبی وجود ندارد**.

## ۵) هفت گام رستاخیز (منطق `resurrect-ultimate.sh`)

1. **توقف تمیز:** فلگ `.prod-stop` + خاتمه سرور/نگهبان/کارگر (درس OOM: بیلد هم‌زمان با سرور = مرگ).
2. **کد:** `git fetch origin main` → `checkout -f -B main` → `reset --hard` (خود-هم‌ترازساز؛ درخت محلی هرچه باشد، برابر main می‌شود).
3. **داده:** زنجیرهٔ بند ۳ (زنده → قلعه → چرخشی → بقا) + مهر نسخه‌های معیوب.
4. **راز (PN-043-A):** بلوک Secret priority — `upload/.runtime/boot-secrets.json` (۱) → `upload/.runtime/` (۲) → `env.escrow.enc` (۳)؛ فقدان هر سه = FATAL؛ سپس escrow سه‌مکانی restore + بارگذاری `.env.local` (تحمل‌پذیر به غیبت).
5. **بیلد:** `bun install` → `prisma generate` → `prisma db push` → `bun run build`.
6. **بوت:** `scripts/start-prod.sh` → دیمن نگهبان (double-fork) → سرور standalone → Worker توسط supervisor.
7. **تأیید:** حلقهٔ وارسی `/api/version` تا ۱۲۰ث؛ `gitSha == HEAD` وگرنه شکست صادقانه. قانون ۱۱ در EXIT:
   در هر شکست میانی، سرور از بیلد موجود دوباره سرو می‌شود.

## ۶) پس از هر بازیابی (چک‌لیست)

1. مهر `/api/version` = HEAD (drift.match=true) + شمارش DB در برابر `upload/.survival/expected-counts.json`.
2. سوئیت گاردها (`scripts/pn042/run-guards.sh`) — همه سبز.
3. دو-سبز ×۲ (قانون ۹ — دو اجرای پیاپی تست‌ها سبز).
4. اگر داده از لایه‌ای غیر از زنده بازگشته: ثبت شاهد (منبع، شمارش، md5) در گزارش جلسه.
5. ثبت حادثه در نقشهٔ وقایع (زمان تشخیص/علت/روش/مدت/درس).

## ۷) چرا سازوکارهای قبلی منسوخ شدند (درس‌های مکتوب)

- **اسکریپت‌های محلی (PN-034…PN-041):** خودِ ابزار نجات در محیطی زندگی می‌کرد که ریست پاکش می‌کرد —
  در ریست ۰۳:۱۰ نگهبان، کد را از mainی گرفت که پلتفرم به چک‌پوینت کهنه بازنویسی کرده بود (فاجعهٔ غیبت PN-041-R).
- **بوت-گارد خودکار:** همان «تفکرِ» منحرف‌کننده را به بوت تزریق کرد؛ کند، شکننده و نرخ-محدود.
- **remote های چندگانه بدون origin:** سپر عالی در آخرین وضعیت به‌دلیل غیبت remote `origin` قرمز بود
  (شاهد baseline جلسهٔ ۰۷۰) — فرسودگی بی‌صدای سازوکار موازی.
- راه‌حل: منطق نجات فقط یک‌جا (گیت‌هاب) · اجرا فقط یک‌شکل (curl) · تأیید فقط یک‌معیار (مهر زنده).

## ۸) محدودیت‌های صادقانه

- raw URL گیت‌هاب تا چند دقیقه پس از پوش ممکن است نسخهٔ کش‌شده بدهد؛ گارد sha256 را داور می‌کند و
  فرمانِ مالک همیشه از main می‌گیرد (کش در بدترین حالت = یک کامیت عقب‌ترِ همان سلسله، نه نسخهٔ کهنهٔ منطقی).
- forbid-rollback اگر Branch Protection فعال باشد نقش نگهبان دوم دارد (BP خودش force-push را می‌بندد)؛
  تا فعال‌سازی مالک، تنها دیوارِ خودترمیم است.
- اگر شبکه قطع باشد: fetch ناموفق → رستاخیز با درخت محلی ادامه می‌دهد (قانون ۱۱) و شکستِ بیلد →
  سرو از بیلد موجود — سرور هرگز بی‌سرو نمی‌ماند.

## ۹) ضمیمهٔ PN-042-A (شورا-ن۰۷۹ · ۲۰۲۶-۱۰-۱۹) — کشف‌ها و اصلاحات

1. **مخزن خصوصی = raw با توکن:** یک‌خطی ناشناس ۴۰۴ می‌داد (مانع اصلی live-test جلسهٔ قبل، نه کش). کل زنجیره (سربرگ اسکریپت · گارد بند ۵ · راهنمای dev-entry · متن Issue اکشن shield) به شکل احرازشده اصلاح شد.
2. **انتقال راز PN-043-A:** نسخهٔ پایدار `upload/.runtime/boot-secrets.json` پیش از این موجود و هم‌ارز بود (شاهد md5 مقادیر)؛ انتقال قیدالامر انجام و `db/.runtime/` با راستی‌آزمایی md5 حذف شد (بکاپ برگشت‌پذیر در `upload/.data/runtime-backup-*`). اپ در شفای بعدی، لایه‌ها را سه‌گانه بازمی‌سازد (طرح PN-012-B).
3. **خطر reset-guard:** کارِ بدونِ کامیت = خورده‌شده توسط گاردِ BUILD-STALE (هر چرخهٔ Worker: `git reset --hard` به آینه). درس: **پس از هر پچ، بی‌درنگ کامیت + پوش**. (این همان عاملی بود که در همین جلسه یک‌بار پچ‌ها را بلعید و دوباره اعمال شدند.)
4. **باگ بیلد در محیط Worker:** recover گارد `bun install && bun run build` را بدون `prisma generate` در محیط اسپاون‌شدهٔ Worker اجرا می‌کند → شکست مکرر «generate is not a function» (سقوط امن: سرور با بیلد قبلی ادامه می‌دهد). در شل کامل، همان توالی سبز است (شاهد build-repro.log). رستاخیز خودش `prisma generate` دارد → مصون.
5. **Branch Protection:** روی پلن رایگان برای مخزن خصوصی غیرممکن است (۴۰۳ از هر دو API کلاسیک و Rulesets — شاهدها در جلسهٔ PN-042-A). تصمیم با مالک: ارتقای پلن یا عمومی‌کردن مخزن.
6. **شاهد اثبات دکترین:** `download/pn042a/live-test-execution.log` — fetch واقعی از گیت‌هاب + صفر مداخلهٔ داده (۲۷٬۸۶۸) + Secret source اولویت ۱ + بیلد سبز + **✅ RESURRECTION COMPLETE در ۸۹ ثانیه**.
