# melka-proxy — راهنمای مالک (PN-030 · لایهٔ ۱)

**سند:** ملکا-شورا-ن۰۳۵-۱۴۰۵ · جلسهٔ فوق‌العاده ۰۳۵ (۱۴۰۵/۰۷/۲۱)
**هدف:** رفع کامل قطع اتصال به سامانه‌های ملک تبریز — بدون تماس با ملک تبریز، بدون VPS، صفر هزینه.

## چرا؟ (خلاصهٔ یک‌خطی)

فایروال ملک تبریز رنج ASN کانتینر ملکا (Alibaba Cloud) را بلاک کرده است.
این Worker ترافیک ملکا را از شبکهٔ Cloudflare (غیربلاک) به API های ملک تبریز می‌رساند.

## کل اقدام شما (۱۵ ثانیه + یک OTP)

```
۱) bash deploy.sh          ← همین پوشه — تأیید OAuth کلودفلر در مرورگر (۱۵ ثانیه)
۲)GLM پرچم آفلینی را برمی‌دارد و تست می‌کند
۳) در تنظیمات عمومی ← «ورود مجدد به ملک تبریز» ← ارسال کد ← OTP (۳۰ ثانیه)
```

## پیکربندی

| قلم | کجا | مقدار |
|---|---|---|
| `MELKA_PROXY_SECRET` | wrangler secret (سمت Worker) | همان `MELK_PROXY_SECRET` در `env.platform.json` کانتینر |
| `MELK_ARM_PROXY_URL` | `env.platform.json` (سمت ملکا) | `https://melka-proxy.<account>.workers.dev` — خودکار توسط `deploy.sh` |

## چهار قید امنیتی مصوب شورا (بخش ۳.۱ سند)

1. **Whitelist میزبان** — فقط `arus-api` / `pm-api` / `gap-api` ملک تبریز؛ هیچ مقصد دیگری عبور نمی‌کند.
2. **احراز HMAC-SHA256** — هر درخواست با `X-Melka-Signature` امضا می‌شود؛ راز فقط در دو سر (ملکا + Worker) است.
3. **پنجرهٔ ±۵ دقیقه** — درخواست قدیمی‌تر از پنج دقیقه رد می‌شود (ضد replay).
4. **صفر لاگ محتوا** — Worker هیچ بدنه/هدر/توکنی ثبت نمی‌کند؛ فقط شمارندهٔ درون‌حافظه.

## هزینه

صفر ریال — پلن رایگان Cloudflare Workers: ۱۰۰٬۰۰۰ درخواست/روز.
(مصرف روزانهٔ ملکا در حالت عادی بسیار کمتر از این سقف است؛ حالت آفلینی PN-029 هم اکنون صفر درخواست می‌فرستد.)

## اگر Cloudflare هم بلاک بود (پلن B — آماده)

پروکسی معکوس از دستگاه مالک: تونل رایگان `localhost.run` یا `serveo.net` از دستگاه مالک (IP ایران) به کانتینر.
کد پروکسی همان می‌ماند؛ فقط `MELK_ARM_PROXY_URL` به نشانی تونل تغییر می‌کند (۱۵ دقیقه).

## تست محلی (اختیاری — برای GLM)

```
MELKA_PROXY_SECRET=<راز> npx wrangler dev     # پورت ۸۷۸۷
# سپس از کانتینر ملکا: MELK_ARM_PROXY_URL=http://127.0.0.1:8787 (فقط برای تست محلی)
```
