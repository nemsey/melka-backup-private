## گام الف — درک فراکامل از خواستهٔ مالک + شناخت زندهٔ عمیق (۱۱ پراب + ۱ آزمون تعیین‌کننده)

مطالعهٔ چندین‌بارهٔ دستور مالک + هر دو گزارش مبنا + دو اسکرین‌شات پیوست (OCR کامل):
- اسکرین‌شات ۱ = «تاریخچهٔ تغییرات آگهی» **۵۷۸۱۰** (سیدی): ۱۸ مدخل از «ایجاد مشاور ۱۸:۴۵|۱۴۰۵/۰۶/۰۲» (عین createdAt تا ثانیه) تا «ویرایش آگهی ۲۰:۰۶|۱۴۰۵/۰۸/۱۸».

- مثال مالک: ایجاد مشاور ۱۴۰۵/۰۶/۰۲ → ۱۴۰۵/۰۷/۰۵ و انتشار آگهی ۱۴۰۵/۰۶/۰۳ → ۱۴۰۵/۰۷/۰۶ = **همان Δ = +۳۴ روز** → قاعدهٔ آبشار: جابه‌جایی نسبی همهٔ مدخل‌ها و رویدادها با Δ لنگر («متناسب با تاریخ اعلامی مالک»).

### کشف‌های زندهٔ این نوبت (پراب‌های ۱-۱۱ — همه از طریق رلهٔ ترموکس):

| مسیر | وضعیت | شاهد |
|---|---|---|

### آزمون تعیین‌کنندهٔ semantics (روی ۵۵۹۲۰ — کاملاً بازگشت‌پذیر):
`PUT requests/update` با آرایهٔ `status` ناقص → **مدخل دیگر حذف شد (REPLACE کامل)** → بازگانی با آرایهٔ کامل عینی → تأیید ۲/۲. نتیجه: **هرگز آرایهٔ ناقص فرستاده نمی‌شود** — به همین دلیل «تغییر تاریخ تاریخچهٔ آگهی» پشت «دروازهٔ خواندن کامل» قرار گرفت (واریانت‌ها آماده‌اند؛ به‌محض انتشار مسیر توسط آرم، خودکار کامل می‌شود) و آرایهٔ status فقط برای درخواست‌ها (که `requests/history` کامل می‌دهد) بازنویسی می‌شود.

## گام ب — چهار عملیات (variables منبع یگانه + executor + purge + ۴ روت OWNER-only)

- **تغییر اطلاعات مالک آگهی**: `properties/owner/{id}` → `PUT users/update/{userId}` با {firstName, lastName, mobileNumber} (عین users/create) + جایگزین `_id` + راستی‌آزمایی زنده + به‌روزرسانی آینه‌های M1/فایل آگهی.
- **تغییر تاریخ + آبشار (کدآگهی)**: لنگر = «ایجاد مشاور» = createdAt (سند زنده)؛ Δ = هدف − لنگر (ساعت صریح → دقیقاً همان ساعت عین ۰۹۹؛ ساعت خالی → حفظ زمان دقیق لنگر حتی ثانیه)؛ آبشار کامل «رویداد و بازخورد» با `request-events/update` (+جایگزین حذف/ثبت دوباره) + راستی‌آزمایی زنده + آینهٔ محلی + پیش‌نمایش قبل/بعد در UI با همان توابع سرور.
- **تغییر تاریخ + آبشار (کددرخواست)**: شاهکار ۰۹۹ تعمیم‌یافته — آرایهٔ status کامل با همان شناسه‌ها و Δ نسبی + بدنه از رکورد محلی یا `requests/info` زنده + آبشار رویدادها + راستی‌آزمایی زنده + شاهد armSyncJson.
- **حذف (هر دو)**: حذف رویدادهای ARM (مسیر اثبات‌شده) → تلاش واریانت‌های حذف رکورد (آمادهٔ فعال‌شدن آرم) → **پاکسازی کامل محلی**: کدآگهی ۱۱ خانواده (کاتالوگ M1، فایل آگهی، رویدادها، بازدیدها، کارگزاری‌ها، معاملات، قراردادها، رد تطبیق، هشدار فرصت، گره/یال گراف) · کددرخواست ۸ خانواده (رکورد + cascade رویداد + …) → راستی‌آزمایی «هیچ اثری باقی نماند» — پروفایل کارشناسان از همین آینه‌ها تغذیه می‌شود.
- حالت تمام‌ظرفیت (گام سوم) پابرجا: هر عملیات نوشتاری خودکار نشست را فعال می‌کند (توقف فهرست‌ها + اولویت ۱۰ رله).
