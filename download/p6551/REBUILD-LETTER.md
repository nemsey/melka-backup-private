## ۴ — گام‌های بازسازی (به همین ترتیب، بدون حذف هیچ گام)

> ✅ یعنی همین گام روی همین بسته **واقعاً اجرا و سبز شده** (قرنطینهٔ P6550 — شاهد در BUILD-INFO.txt بسته).

### گام ۰ — آماده‌سازی
1. یک پوشهٔ کاری تازه بسازید؛ `melka-source-v1.0-20261004.tar.gz` را **در قرنطینه** استخراج کنید.
2. `md5sum -c MANIFEST.md5` → باید ۸۲۷/۸۲۷ «OK» باشد. ✅

### گام ۱ — نصب و صحت نوع
3. `bun install` → سبز (۸۵۷ پکیج). ✅
4. `bunx prisma generate` → سبز. ✅
5. `bunx tsc --noEmit` → **صفر خطا**. ✅

### گام ۲ — پایگاه داده (خالی و قانون‌مند)
6. `.env.example` را به `.env.local` کپی کنید و این سه مقدار را بدهید:
   - `DATABASE_URL=file:<مسیر>/db/custom.db`
   - `MASTER_ACCESS_CODE=` **کد ۸رقمی انتخابی مالک — هرگز مقدار پیش‌فرض در بسته جا نگذارید**
   - `MELK_TOKEN_KEY=` خروجی `openssl rand -hex 32`
7. `bun run db:push` → اسکیمای ۳۹ مدل ساخته می‌شود (بدون هیچ داده‌ای).
8. `bun run test` → باید سبز باشد (پایگاه تست خودکار جدا ساخته می‌شود). *(چند تست ممکن است به کد مدیر محیطی حساس باشد — پیش از اجرا `MASTER_ACCESS_CODE` همان محیط را ست کنید.)*

### گام ۳ — اجرا و بیلد
9. `bun run dev` → پورت ۳۰۰۰ → صفحهٔ ورود فارسی → ورود با کد مدیر → خانهٔ پنج‌کاشی‌ای.
10. `bun run build` → سبز؛ BUILD_ID خودکار `<sha8>-<yyyymmdd>-<hhmm>`. ✅
11. راستی‌آزمایی سه‌مسیرهٔ نسخه: `GET /api/version` · متاتگ `app-build-id` در HTML · فوتر داشبورد — هر سه باید یک مقدار بدهند. *(قرارداد پایدار — AGENTS.md §۴)*

### گام ۴ — اتصال داده (فقط با ورود مالک)
12. تنظیمات عمومی → «اتصال ملک تبریز» → ورود با **کد پرسنلی واقعی مالک در سامانهٔ ARM** → کد پیامکی → توکن‌ها خودکار در Vault (AES-256-GCM) ذخیره می‌شوند.
13. دیمن کاتالوگ خودکار آغاز می‌کند: برش‌های checkpointدار `properties/list` و `requests/list` + غنی‌سازی زنجیره‌ای (`owner/details/applicant`) + پرسنل PM. **صبر کنید — هیچ دادهٔ دستی وارد نکنید.**
