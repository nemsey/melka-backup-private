## ۴. معماری تحویل‌شده

```
MemoryStore (درگاه)  ⇢  InMemoryStore (پیش‌فرض) / FileSystemStore (JSONL الحاقی، بارگذاری تنبل، صلب در برابر خط خراب)
VectorIndex          ⇢  تعبیه هش FNV-1a قطعی ۶۴بعدی (نرمال‌سازی ارقام فارسی/عربی، ZWNJ-آگاه) + کسینوسی + topK پایدار
MemoryEngineImpl     ⇢  قرارداد v1 (append/query — خروجی دقیقاً ۷ فیلد) + retrieveSimilar (رتبه‌بندی برداری، محدوده tileId)
                        + consolidate (خود-توان: جذب‌شدگان از داوطلبان بعد حذف؛ اصل‌ها هرگز حذف نمی‌شوند) + stats + reindex
ContextEngineImpl    ⇢  قرارداد v1 (buildContext — هم‌ارز شکل با Placeholder) + assemble (حافظه مرتبط + سیگنال‌های زنده
                        + بودجه توکن ۲۰۴۸/۴نویسه + WorkingContext سریال‌پذیر) + قراردادهای قابلیت اختیاری ContextAssembler/ContextMemoryRetriever
BaseIntelligentAgent ⇢  observe(kind,payload,layer) — fire-and-forget؛ assembleContext(purpose,opts) — null بدون قابلیت
```

**اصل حاکم — وفاداری به قرارداد:** قراردادهای v1 (PHASE 3) «حداقل» امضای موتورها ماندند؛ همه قابلیت‌های غنی «متد افزودنی روی کلاس» یا «قرارداد قابلیت اختیاری جدا» هستند. نسخه قرارداد ۱ دست‌نخورده.

## ۷. کشف‌های صادقانه حین اجرا (سه اصلاح خود-افشا)

1. **شکاف خود-توانی consolidate:** اجرای مکرر، رکوردهای جذب‌شده را دوباره گروه می‌کرد → اصلاح: حذف `mergedIds` ادغام‌های قبلی از داوطلبان (نماینده زنده می‌ماند تا با ورودی جدید رشد کند) + تست idempotency
2. **نمایه خالی فروشگاه فایل تازه‌ساز:** `retrieveSimilar` چیزی نمی‌یافت → اصلاح: همگام‌سازی تنبل خودکار + `reindex()` صریح + تست بین-نمونه‌ای
3. **درس تست:** «ائل‌گلی» با ZWNJ دو توکن می‌شود (۵ توکنی vs ۴ توکنی → امتیاز ۰٫۶۳۲۵ vs ۰٫۷۰۷۱) — انتظار اشتباه اولیه تست اصلاح و در تست مستند شد
