پرامپت قانون تثبیت و بقای نسخهٔ ملکا
(ملکا-شورا-۱۴۰۵-۰۳۱ · نسخهٔ ۱٫۰)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

اجرای کامل این پرامپت، شرط «انجام‌شده» تلقی‌شدنِ دستور اصلی است.
در پاسخ پایانی، وضعیت صریح هر بند (الف تا یا) را با شاهد اعلام کن.

─────────────────────────────────────────────────
الف) مرز کار
─────────────────────────────────────────────────
فقط تغییرات همین دستور. هیچ تغییر اضافه‌ای — هرچند بهبود —
بدون مجوز جداگانه ممنوع. خطا دیده شد؟ فقط گزارش کن.

─────────────────────────────────────────────────
ب) تثبیت پله‌ای + توقف اضطراری
─────────────────────────────────────────────────
- پس از هر گام بزرگ (نه فقط پایان): کامیت با شمارهٔ پرونده.
- معیار توقف اضطراری (هریک رخ داد → کار جدید متوقف):
  • ۷۵٪ ظرفیت بافتار مصرف شد
  • ۵ پیام بدون تثبیت گذشت
  • ۲ ساعت بدون کامیت گذشت
- قانون مبادله: در تنش «پیشرفت vs تثبیت»، تثبیت برنده است.

─────────────────────────────────────────────────
ج) بستهٔ بقا در پوشهٔ upload
─────────────────────────────────────────────────
محتویات اجباری:
  ۱. بستهٔ کامل git (همهٔ شاخه‌ها و تاریخچه)
  ۲. کپی پشتیبان دیتابیس
  ۳. کپی کامل worklog
  ۴. مانیفست شواهد + md5 فایل‌ها
  ۵. configuration files (env، settings)
  ۶. شواهد بصری (screenshots)
  ۷. فهرست وابستگی‌ها (package.json + lock)

نام‌گذاری: [شماره پرونده]-[تاریخ]

─────────────────────────────────────────────────
د) مهر نسخه
─────────────────────────────────────────────────
۱. نوسازی سرور تا buildId با کامیت همراستا شود.
۲. راستی‌آزمایی مهر روی preview:
   • خروجی GET /api/version
   • اسکرین‌شات از تغییر کلیدی
۳. تا راستی‌آزمایی سبز نشود، پرونده بسته نیست.

─────────────────────────────────────────────────
هـ) گزارش صادقانه
─────────────────────────────────────────────────
- الحاقیهٔ پایان جلسه در worklog.
- هر ادعا: با شاهد (فایل، خروجی، اسکرین‌شات).
- اگر ناتمام است: صریح بنویس.
- گزارش ناقصِ صادق > گزارش کاملِ بی‌شاهد.

─────────────────────────────────────────────────
و) وارسی آغاز جلسهٔ بعد
─────────────────────────────────────────────────
پیش از هر کار:
  • HEAD مخزن
  • مهر نسخهٔ زندهٔ preview
  • شمار ردیف‌های کلیدی DB
  • وجود کامیت آخرین پرونده
  • وجود بستهٔ بقای upload
اگر بازگشت رخ داده: بی‌درنگ گزارش + طرح بازیابی +
تا اجازهٔ مالک، هیچ کار جدیدی آغاز نکن.

─────────────────────────────────────────────────
ز) دادهٔ مقدس
─────────────────────────────────────────────────
- پیش از هر عملیات پرریسک DB: پشتیبان نقطه‌ای در upload.
- صفر حذف/بازنویسی بدون دستور صریح مالک.
- دادهٔ سامانهٔ ملک تبریز مقدس است.

─────────────────────────────────────────────────
ح) نقشهٔ وقایع (Audit Trail) — [افزودهٔ شورا]
─────────────────────────────────────────────────
هر بستهٔ بقا باید فایل وقایع داشته باشد شامل:
  • تاریخچهٔ کامیت‌های این پرونده
  • خطاهای رخ‌داده
  • بازیابی‌های انجام‌شده
  • تاریخ‌های دقیق و ساعت
هدف: اگر ریست رخ داد، بدانیم دقیقاً چه شد.

─────────────────────────────────────────────────
ط) Tier-aware بودن تثبیت — [افزودهٔ شورا]
─────────────────────────────────────────────────
هم‌راستا با جلسه ۰۲۵:
  • Tier 0-1: تثبیت استاندارد
  • Tier 2-3: تثبیت + آینهٔ برون‌پلتفرمی
  • Tier 4: تثبیت + آینه + زنجیرهٔ هش + وارسی مستقل

─────────────────────────────────────────────────
ی) حق بازگشت (Rollback Right) — [افزودهٔ شورا]
─────────────────────────────────────────────────
- مشخص کردن commit hash قبل از شروع کار.
- اگر نسخهٔ خراب کامیت شد: بازگشت به hash قبلی.
- صفر کامیت غیرقابل بازگشت.

─────────────────────────────────────────────────
ک) زنجیرهٔ هش (Hash-Chain) — [افزودهٔ شورا]
─────────────────────────────────────────────────
هر بستهٔ بقا، هش بستهٔ قبلی را حمل کند:
  • بستهٔ ۱ → هش X۱
  • بستهٔ ۲ → هش X۲ + X۱
  • بستهٔ ۳ → هش X۳ + X۲ + X۱
اگر بسته‌ای گم شد، از زنجیره می‌فهمیم. دستکاری‌ناپذیر.

─────────────────────────────────────────────────
ل) وارسی مستقل بیرونی — [افزودهٔ شورا]
─────────────────────────────────────────────────
زمان‌بندی خودکار (نه فقط دستی):
  • هر ۶ ساعت: پوش خودکار به مخزن برون‌پلتفرمی
  • هر ۲۴ ساعت: راستی‌آزمایی هش با نسخهٔ محلی
  • هر هفته: گزارش خلاصه به مالک
